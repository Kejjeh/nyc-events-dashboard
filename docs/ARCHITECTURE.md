# Architecture

## Why it's shaped this way

GitHub Pages serves static files only, so all data work happens at build time in
CI. The pipeline's output (`public/data/*.json`) is **committed** so that a run
where every source fails still deploys yesterday's data, and so the UI build is
reproducible. Everything else follows from two constraints: free-tier API quotas
(spend-limiting), and flaky sources (carry-forward).

## Data flow

```
GitHub Actions (cron 11:00/23:00 UTC, push, manual)  [deploy.yml]
  npm test
  npm run build:data                                  [src/pipeline/run.ts]
    1 fetch     sources.ts: 17 fetch<Src>() in parallel, each wrapped in
                settle() — a throwing source is logged and EXCLUDED from
                succeededSources; push runs skip ticketmaster/serpapi/jambase
    2 assemble  assemble.ts: NORMALIZERS[source](record) → Event; bad records
                dropped; per-source dedup by id
    3 carry     carryForward.ts: previous live+archive events whose source is
                NOT in succeededSources are kept; then everything before
                today (ET) is dropped
    4 dedup     dedup.ts: same title+venue+date across ticketing sources →
                one canonical event (richest wins) + altTicketLinks
    5 partition partition.ts: live = city ∈ LIVE_CITIES ('New York') AND
                start ≤ now+120d; everything else → archive
    6 enrich    enrichmentChain.ts over live: geocode → neighborhood →
                weather → spotify; archive gets neighborhood only (skipped
                on push). Caches to public/data/neighborhood-cache.json.
    7 write     events.json {generatedAt,count,places,sources,events} +
                archive.json; places = state→city event counts for the UI
  git commit data [skip ci]  (reset+reapply on race, never rebase JSON)
  npm run build → deploy Pages

Browser
  useEvents ── events.json (eager)          App.tsx (all state lives here)
  useArchive ─ archive.json (lazy, only     filters.ts: toCriteria→filterEvents
               when selection ≠ NY/NYC)                 →sortEvents→slice(60)
  urlState.ts keeps filters ⇄ URL (?state=&city=&cat=...) via replaceState
```

## Key abstractions

- **`Event`** (`src/domain/event.ts`) — the one shared model. Required:
  id, title, category, venue, start, isFree, url, source. `city`/`state`
  default to New York/NY when absent — most sources never set them.
- **`RawBatch`** `{source, records: any[]}` — what every fetcher returns.
  Fetch (I/O, in `sources.ts`) is strictly separated from normalize (pure,
  in `src/ingestion/`), which is why normalizers are easy to test.
- **`EnrichmentStage`** `{name, skipOnPush?, run(events, ctx)}` — stages are
  data; `run.ts` only supplies context (keys, previous events, onPush) and logs.
- **Injectable seams** — every enricher and fetch helper takes its network
  function as a defaulted last parameter; tests inject fakes, prod uses defaults.
- **Location drill-down** — pure transitions in `ui/filterSelection.ts`:
  State → City → (NYC only) Borough → Neighborhood; each step resets the ones
  below it. Non-NYC cities get a flat neighborhood chip row.

## Geo resolution (two layers)

1. Ingest time: point-in-polygon against bundled 2020 NTA + borough polygons
   (`src/ingestion/data/*.json`, regenerated by `scripts/build-*-polygons.mjs`).
   NYC helper: `nycLocationFromLatLng`; non-NYC: `locality.ts` nearest-metro.
2. Enrich time: sources without coordinates (GEOCODEABLE_SOURCES in
   `geocodeEnrich.ts`) get Google-geocoded; `neighborhoodEnrich.ts` then
   overwrites NTA names with Google reverse-geocode names, cached per rounded
   lat/lon in `neighborhood-cache.json` (nulls cached too, to stop retries).
   A wrong neighborhood is treated as worse than none — no guessing.

## Boundaries a change typically crosses

- **New source**: `src/ingestion/<src>.ts` (+test) → `sources.ts` →
  `assemble.ts` → `run.ts`. Nothing else.
- **New filter/UI axis**: `filters.ts`/`filterSelection.ts` (+tests) →
  `urlState.ts` (+tests) → `App.tsx` wiring.
- **New enrichment**: new `<x>Enrich.ts` (+test, seam pattern) → stage entry in
  `enrichmentChain.ts` → maybe a key in `deploy.yml` env block.
- **Payload shape change**: `run.ts` writer + `useEvents`/`useArchive` readers +
  anything reading `places`/`sources` in `App.tsx`. Keep old fields until the
  next data refresh commits, or the deployed UI breaks against old JSON.

## Ordering invariants (do not reorder)

carry-forward → dedup → partition (dedup must see carried events; partition
must see deduped set). Geocode before neighborhood (fresh coords unlock
lookups). Spotify seeds from `previousLive` read before partition.
